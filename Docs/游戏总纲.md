# OutpostLoop 游戏总纲

本项目是一款高位斜俯视的轻量即时战略守城游戏。玩家从一名指挥员和局外资金起步，自选地点建立基地，再用建筑生产采集员和守军。采集员自动采运，守军和炮塔自动交战。守住主基地并消灭最后一波敌人即可结算，新局使用新种子。

首个完整可玩版以[已确认的 v0.7 玩法设计](首版玩法设计.md)为准。下方原型基线用于试玩对照，实施状态以执行总清单为准。

## 已确认的游戏设定

2026-11-10，用户确认以下简版大纲。

- 玩家是众多普通穿越者之一，亲自往返于安全的出发地和正在打仗的世界，在当地采集、建设和作战。
- 玩家平时生活在类似《井口战役》演变空间的独立局外空间，从那里接任务、出发并回归。此项由用户于 2026-11-10 补充。
- 各世界的地形、材料和技术条件不同，可用装备和打法随当地条件而变。
- 完成任务后可以安全回归，将带回的情报和研究用于下一次行动。失败后重开属于游戏规则，故事层面的死亡与重开关系待定。

参战方、参战原因、穿越的具体机制和剧情留待后续确认。历史故事稿已否决，只保留作过程记录。

## 方向与设计约束

- **已确认的方向**借鉴《亿万僵尸》的发展基地和守潮目标，以及《红色警戒》的建造、生产和调度。玩家以少量指令作出策略决定，单位负责执行细节。
- **当前原型基线**采用 12 分钟、六波、有限地图与四向防线。这个基线用于比较每次试玩结果。数值和内容数量可在有证据时调整。
- **首个玩法里程碑**是一张地图上一局能玩出不同打法。优先经济和优先防御都应有可行路径，也应在中盘面对不同的资源或防线压力。
- 单局地图、设施和敌人规模有上限。跨局胜场解锁下一局的起始资金档位，起始资金最高 1,000。玩家在新地图重新选择基地、资源和防线。
- 首版验收在 Unity 编辑器完成。正式视觉需先展示预览并获明确确认。横屏触屏、设备性能与成品构建各自有独立验收条件。

## 一局如何展开

| 阶段 | 玩家看到什么 | 玩家要决定什么 | 系统如何反馈 |
| --- | --- | --- | --- |
| 开局准备 | 单局目标、起始资金档位和下一档条件 | 进入新种子的地图后，指挥员往哪里走、基地放在哪里 | 主基地启用后开放外围建造并开始调度敌袭 |
| 第一波前 | 主基地、矿点、资金和建造侧栏 | 第一笔钱先用来建立采集收入，还是先建防线 | 显示资金、建筑价格、占地、施工与生产结果 |
| 中盘 | 剩余资源、现有建筑耐久、已入场的敌人 | 是否开发新方位，哪里用固定设施守，哪里靠机动小队补位 | 展示资源耗尽、训练完成、外围损失和战场敌情 |
| 最后一波 | 已入场敌群、基地和防线状态 | 把资金投给修复、火力或防线 | 清完最后一波即获胜，基地被摧毁立即失败 |
| 结算和重开 | 击退数量、胜败原因、胜场进度 | 决定是否开下一局 | 同一局胜场只记录一次，新局按当前档位发放资金 |

## 系统职责

| 系统 | 玩家做的决定 | v0.7 玩法 | 首版需要验证 |
| --- | --- | --- | --- |
| 地图和镜头 | 读地形与方位，判断哪里值得投入 | 高位透视镜头可平移、旋转和缩放，焦点可回到指挥员或基地。种子改变资源布局与来向 | 默认视角能看清单位。移动镜头后仍能正确选址 |
| 基地 | 选择主基地位置，在采运、炮塔和基地耐久之间分配预算 | 主基地由玩家落位，有耐久和三条升级线 | 选址后可建范围和敌人目标正确。扣费和修复结果可读 |
| 资金 | 选择从哪里建立收入、什么时候投资采集站 | 采集员从有限矿点往返采运，卸货后入账 | 最低起始档能建立收入，耗尽、运回和入账可核对 |
| 建造 | 选择设施、位置和开工时机 | 建筑使用同一余额付费，在网格上选址。开工后显示施工进度，完工才生效 | 建筑位置改变采集范围、火力覆盖和通行。工期可读，受袭后能决定是否重建 |
| 守军和炮塔 | 决定何时付费训练、把哪支守军派往哪里 | 兵营完工后开放训练，守军和炮塔自动交战 | 调防能改变接敌结果，玩家能预留训练费用和时间 |
| 进攻和结算 | 建立防线，发现敌人后调防，根据战损改下一轮计划 | 六波敌人入场后可见，清完最后一波结算。胜场解锁下一档起始资金 | 玩家发现敌人后有调防机会，能说清失败原因 |

### 操作约定

- 地图和小地图用于查看局势。玩家在地图选址，从生产建筑下单，采集员自动行走、采集、返程和卸货。
- 局内 HUD 提供调防、建造、升级与暂停入口。建造在独立实时侧栏进行，显示库存、地块与价格，地图仍可操作。基地升级有独立入口并暂停局时。
- 当前键鼠入口为左键点选、滚轮缩放、`V` 建造、`B` 升级、`Esc` 暂停。键位是原型方案。触屏操作需要在对应阶段验证点选区域、缩放和面板遮挡。
- 影响生死或投入的操作应在下单前说明对象、成本和结果，在下单后给出成功或失败反馈。本局剩余时间、已入场的敌人和基地受损应在战场上读得出来。

## 首版内容边界

| 优先级 | 内容 |
| --- | --- |
| 首个玩法切片 | 一张有边界的种子地图、主基地选址、单资金经济、两类生产单位、可毁可建的设施、六波进攻与完整结算 |
| 玩法通过后补齐 | 开局引导、战斗和建筑状态反馈、正式地图与单位表现、音效、触屏操作和性能验收 |
| 后续选题 | 更多兵种和生产队列、长期城市经营、多地图内容、联机。进入后续版本时再评估各项与核心体验的关系 |

## 探索、回归与局外成长

玩家在局外选择当前科技能进入的地图。地图按科技时代划分，每次进入都在野外随机出生。新档科技树为空，先从新手地图熟悉移动、探索和建造。玩家可以自己挑地方搭基础庇护所，保证指挥员存活。

| 阶段 | 玩家操作与规则 |
| --- | --- |
| 选图出发 | 查看可进入的科技时代与地图，选择目的地。进入后从野外随机出生点开始探索 |
| 探索与发展 | 探索获得资源，玩家决定把资源投入建造和防御，还是用于研究与升级 |
| 基础任务达成 | 开放主动回归。玩家可随时返回，也可继续探索、研究或挑战终极任务。前期任务主要是简单探索与生存，例如存活游戏内一天或一个月，完成通常只给少量资金 |
| 终极任务达成 | 自动回归并结算。基础任务达成后继续探索的选择，到此结束 |
| 成功回归与再出发 | 资金奖励取决于任务完成情况。科技按本局实际研究结果保留，和任务资金分别结算。回归后可以花资金强化自己，也可以直接选择下一张可进入的地图继续探索 |
| 指挥员死亡 | 本局结束并清空本次出发的内容。已采资源、建筑、任务进度、任务资金奖励和本局研究全部失去，包括已完成但尚未回归的科技。此前已保存的局外资金、科技和强化继续保留 |

局外科技树记录已研究的能力和进阶地图的进入条件。探索带来的资源支撑本局发展，研究成果让玩家打开新的地图选择。基础任务一完成，玩家就要决定现在回归结算，还是继续投入时间与资源争取更多成果。

[v0.10 探索战术扩展](探索战术扩展-v0.10.md)从木工、绳索和手工机械起步。荒野开放给新档，带回「野外测绘」后开放旧工坊，开闸回归后开放山口烽台。三张地图分别考验生存、绕行取材和守备。六波守城使用独立试玩入口和原有胜场档案。

## 待试玩验证的设计

以下是影响首版设计的问题和验证思路。拟采用的整版规则以送审稿列出的版本为准。

| 问题 | 候选规则 | 用什么判断 |
| --- | --- | --- |
| 经济投资是否值得 | 让早期采集站能在承受一次外围风险前回收成本，兵营或炮塔则直接提高一侧防守 | 固定同一个种子，比较先投资采集站与先补薄弱防线时的首笔支出、首波后库存和防线状态 |
| 中盘是否需要重新布防 | 对中盘某一波试做双向或错时进攻。两路敌情分别在入场后可见 | 同一个方向守到底的成本上升，玩家发现第二路敌人后仍能作一次调度或扩建决策 |
| 失败是否能复盘 | 清楚反馈外围建筑损失和主基地失守 | 首次试玩者能用自己的话说明为何失守，以及下一局会改哪一个决定 |

## 特殊任务候选 · 一次性续战

2026-11-10，用户认可把一次性续战作为特殊任务的候选规则。它借鉴《井口战役》中角色返回同一战场继续任务的结构。具体纳入版本和获取方式待定。

- **触发条件**。任务启用续战，本局还有一次机会，指挥员阵亡时己方据点仍在，且本局尚未判负。若阵亡与主基地失守同时发生，以主基地失守结算。
- **玩家选择**。符合条件时可选择消耗一次机会，在己方据点恢复指挥员并继续同一局，也可接受失败。再次阵亡时按任务的失败规则结算。
- **战场状态**。继续时只恢复指挥员。部队、建筑、物资、任务进度和敌军位置沿用阵亡时的状态。已发生的损失继续生效。
- **验证目标**。对照据点与采运线完整、据点还在但防线与采运线严重受损两种局面，观察复活后的首要决策是否不同。另核对复活机会只消耗一次，以及据点失守时直接结算。

## 里程碑

| 阶段 | 交付物 | 完成条件 |
| --- | --- | --- |
| M0 可玩原型 | 编辑器可从 Boot 进入单局，已有采运、升级、实时建造、调防与结算 | 当前基线已跑通。历史验证与已知缺口见执行总清单 |
| M1 核心策略切片 | 一张可完整试玩的地图，支持经济优先和防御优先两条路线 | 同一种子、同一起始补给下，两条路线都能通关，并在中盘呈现可观察的库存、损失或布防差异。换种子复验。真实编辑器试玩者能从界面读出下一步，并说明两条打法的取舍 |
| M2 代表性内容切片 | 一局的开局引导、战斗信息与代表性视觉音效 | M1 通过后，至少一场从开局到结算的真实试玩覆盖正式候选表现。正式视觉预览经用户确认 |
| M3 设备与交付验证 | 横屏输入、安全区、性能以及经授权的设备交付 | 先确定目标设备与预算，再在该设备完成整局和重开，记录输入、帧率、内存与异常。实际构建和发布以相应授权为前提 |
