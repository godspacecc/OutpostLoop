# OutpostLoop 游戏总纲

本项目是一款高位斜俯视、限时单局的轻量即时战略守城游戏。玩家指挥一座前哨基地，决定开采哪片资源、扩建哪一侧、把机动守军调到哪里。工人自动采运，守军和炮塔自动交战。基地在时限内守住最终进攻，玩家即可结算并在新地图上再开一局。

首个完整可玩版的规则与范围汇总在[首版玩法设计送审稿](首版玩法设计.md)。现有可玩原型提供对照证据。送审版本由用户明确确认后才进入玩法实现。

## 方向与设计约束

- **已确认的方向**借鉴《亿万僵尸》的发展基地和守潮目标，以及《红色警戒》的建造、生产和调度。玩家以少量指令作出策略决定，单位负责执行细节。
- **当前原型基线**采用 12 分钟、六波、有限地图与四向防线。这个基线用于比较每次试玩结果。数值和内容数量可在有证据时调整。
- **首个玩法里程碑**是一张地图上一局能玩出不同打法。优先经济和优先防御都应有可行路径，也应在中盘面对不同的资源或防线压力。
- 单局地图、设施和敌人规模有上限，终局明确。跨局奖励目前用于换取少量开局补给，新局重新安排基地、资源和防线。
- 首版验收在 Unity 编辑器完成。正式视觉需先展示预览并获明确确认。横屏触屏、设备性能与成品构建各自有独立验收条件。

## 一局如何展开

| 阶段 | 玩家看到什么 | 玩家要决定什么 | 系统如何反馈 |
| --- | --- | --- | --- |
| 开局准备 | 单局目标、补给币余额和补给选项 | 这局是否兑换起始物资 | 开局时一次性扣币并入库，进入本局种子的地图 |
| 第一波前 | 核心基地、周边两类资源和本局剩余时间 | 先派工采哪种资源，第一笔库存投向经济还是防线 | 显示工人任务、入库、建造费用、地块和当前建设结果 |
| 中盘 | 剩余资源、现有建筑耐久、已入场的敌人 | 是否开发新方位，哪里用固定设施守，哪里靠机动小队补位 | 展示资源耗尽、训练完成、外围损失和战场敌情 |
| 最后一波 | 倒计时、基地和现有防线状态 | 把最后一笔库存投给修复、火力或防线 | 时限到达时，基地存活且敌群清空即获胜。基地摧毁立即失败，时限到达仍有敌人也判失败 |
| 结算和重开 | 存活时间、击退数量、胜利补给币 | 开新种子并决定是否兑换补给 | 发奖只结算一次，新局使用新的局内状态 |

## 系统职责

| 系统 | 玩家做的决定 | 当前可玩内容 | 首版需要验证 |
| --- | --- | --- | --- |
| 地图和镜头 | 读地形与方位，判断哪里值得投入 | 固定高位镜头默认聚焦基地，可缩放看全图，小地图可派工。种子改变资源布局与来向 | 默认视角能看清基地和附近单位。不同布局会改变开采和布防顺序 |
| 基地 | 在运输、炮塔和基地耐久之间分配预算 | 核心基地、耐久、库存和三条升级线 | 基地危险、扣费和修复结果都可读。升级选择会影响后续几波 |
| 资源 | 选择采废料还是能源、何时改派、是否投资采集站 | 废料和能源是有限资源。点场景或小地图派工，自动往返。采集站与工人共用同一资源余量 | 两类资源都影响局内决策。耗尽、改派和同时开采时库存可核对 |
| 建造 | 在同一地块上选择经济、驻防或拖延进攻，并决定何时开工 | 四个外围地块可建采集站、兵营或路障。四个独立炮位可建塔和迁塔。当前原型下单即建成 | 建造入口直接可达。施工时间可读，完工才生效，外围工地受袭后结果可核对 |
| 守军和炮塔 | 在波前分配机动小队，决定用哪一侧的固定火力 | 一支开局机动小队、兵营自动训练驻军、炮塔自动索敌 | 切换驻防方位能改变接敌结果。一条指令能让整支小队执行 |
| 进攻和结算 | 先建立基本防线，发现敌人后调防，根据战损改下一轮计划 | 原型有六波和主要来向预告，外围建筑可受损和摧毁，并有胜负结算和补给币 | 取消预告后，玩家能从场景和小地图发现已入场敌人并应对，失败原因能说清 |

### 操作约定

- 地图和小地图用于查看局势与派工。选择资源后，工人负责行走、采集、返程和卸货。
- 局内 HUD 提供调防、建造、升级与暂停入口。建造在独立实时侧栏进行，显示库存、地块与价格，地图仍可操作。基地升级有独立入口并暂停局时。
- 当前键鼠入口为左键点选、滚轮缩放、`V` 建造、`B` 升级、`Esc` 暂停。键位是原型方案。触屏操作需要在对应阶段验证点选区域、缩放和面板遮挡。
- 影响生死或投入的操作应在下单前说明对象、成本和结果，在下单后给出成功或失败反馈。本局剩余时间、已入场的敌人和基地受损应在战场上读得出来。

## 首版内容边界

| 优先级 | 内容 |
| --- | --- |
| 首个玩法切片 | 一张有边界的种子地图、一次完整结算、两类资源、可毁可建的外围设施、固定炮位、自动守军和明确的分波进攻 |
| 玩法通过后补齐 | 开局引导、战斗和建筑状态反馈、正式地图与单位表现、音效、触屏操作和性能验收 |
| 后续选题 | 自由选址、更多兵种和生产队列、长期城市经营、多地图内容、联机。进入后续版本时再评估各项与核心体验的关系 |

## 待试玩验证的设计

以下是影响首版设计的问题和验证思路。拟采用的整版规则以送审稿列出的版本为准。

| 问题 | 候选规则 | 用什么判断 |
| --- | --- | --- |
| 经济投资是否值得 | 让早期采集站能在承受一次外围风险前回收成本，兵营或炮塔则直接提高一侧防守 | 固定同一个种子，比较先投资采集站与先补薄弱防线时的首笔支出、首波后库存和防线状态 |
| 中盘是否需要重新布防 | 对中盘某一波试做双向或错时进攻。两路敌情分别在入场后可见 | 同一个方向守到底的成本上升，玩家发现第二路敌人后仍能作一次调度或扩建决策 |
| 失败是否能复盘 | 优先给出外围建筑被毁、基地被突破或终局仍有敌人的可辨别反馈 | 首次试玩者能用自己的话说明为何失守，以及下一局会改哪一个决定 |

## 里程碑

| 阶段 | 交付物 | 完成条件 |
| --- | --- | --- |
| M0 可玩原型 | 编辑器可从 Boot 进入单局，已有采运、升级、实时建造、调防与结算 | 当前基线已跑通。历史验证与已知缺口见执行总清单 |
| M1 核心策略切片 | 一张可完整试玩的地图，支持经济优先和防御优先两条路线 | 同一种子、同一起始补给下，两条路线都能通关，并在中盘呈现可观察的库存、损失或布防差异。换种子复验。真实编辑器试玩者能从界面读出下一步，并说明两条打法的取舍 |
| M2 代表性内容切片 | 一局的开局引导、战斗信息与代表性视觉音效 | M1 通过后，至少一场从开局到结算的真实试玩覆盖正式候选表现。正式视觉预览经用户确认 |
| M3 设备与交付验证 | 横屏输入、安全区、性能以及经授权的设备交付 | 先确定目标设备与预算，再在该设备完成整局和重开，记录输入、帧率、内存与异常。实际构建和发布以相应授权为前提 |

本纲用于决定做什么和做到什么程度。[开发规程](开发规程.md)规定怎么验证和交付。[执行总清单](执行总清单.md)记录每批的状态与证据。[初始设计与计划](初始设计与计划.md)保留原型历史。
