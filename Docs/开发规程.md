# OutpostLoop 开发规程

每批按一段完整玩家流程推进。执行者在开工前明确玩家的目标、操作入口、状态变化与验收方式，完成后用同一条路径实测。执行总清单保留本批结果，玩法规则有变动时同步游戏总纲。

## 开工前确定交付范围

1. 读[游戏总纲](游戏总纲.md)和[执行总清单](执行总清单.md)，核对对应的实际代码、场景和入口。确认当前阶段的验收目标及这批改动要解决的一个玩家问题。
2. 写出玩家路径。至少覆盖「看到入口 → 发出指令 → 规则校验 → 看见结果 → 回到战场或结算」。涉及多个入口时，一并梳理它们的职责、按键或点击方式，以及是否推进局时。
3. 明确玩法事务。写清前置条件、扣费和生效时机、失败反馈，以及暂停、重复操作、库存不足、终局或重开时的行为。资源、建造和生产共享状态时，指定状态归属与更新顺序。
4. 定义验收。给出可复现的起点、玩家输入和期望结果。策略改动同时写清对照种子、两条打法、观察波次和要记录的差异。界面改动同时写清需要检查的分辨率、遮挡和返回路径。
5. 将目标、范围、验证方式和状态登记在执行总清单。紧邻当前工作的一段计划足以开工，常规技术选型由执行者解决。改变已确认的玩法方向或正式视觉采用时，准备可供评审的方案或预览，并按仓库授权边界推进。

### 开工卡

| 项目 | 填写内容 |
| --- | --- |
| 目标 | 玩家遇到的问题、所属里程碑、完成后应能做的事 |
| 玩家路径 | 开始状态、入口、操作、即时反馈、退出或恢复路径 |
| 规则与异常 | 状态所有者、成本、时序、允许状态、失败与恢复 |
| 受影响范围 | 局时、资源、UI、输入、存档、表现中实际涉及的部分 |
| 验收与证据 | 完整交互方法或测试类、最多用例数、试玩脚本、截图和日志目录 |

## 实现与联调

- 先把规则接到本局的权威状态，再接系统命令、输入和显示。界面读状态、发命令。扣费、库存、耐久和结算由规则层处理。
- 在同一批完成玩家入口、必要说明、操作反馈及失败反馈。检查通过该功能正常进入、离开、再进入的完整流程。界面应在合适的层级显示，点击面板时要核对地图是否也收到同一次输入。
- 复用已有基础框架和配置。原型调参集中在可查的位置。进入正式化阶段时重新评估配置来源、依赖、资源收集和会话生命周期。核心手写类、方法和字段用中文说明职责。
- 临时几何体可支持整局试玩。正式美术和动画先提供对应实机场景预览，经用户明确确认后再作为正式资源采用。历史参考项目和本项目各自维护资产与数据。

## 验证与试玩

| 验证 | 必查内容 | 证据 |
| --- | --- | --- |
| 规则 | 正常执行、失败不扣费、重复提交、暂停和终局等受影响边界 | 真实完整 testMethod 或非空 testClass，先声明范围和最大数量。Unity MCP 使用 `includePassingTests=true`，CLI 保留含通过项的完整 XML |
| 真实入口 | 从 Boot 进入可玩场景，通过实际按钮或输入走完整路径。检查 UI 层、镜头、提示、返回、暂停和重开 | 用本项目 Unity MCP 验证并保留明细。必要时检查实际输入、画面和 Console |
| 整局体验 | 策略变更覆盖准备、至少一次受影响的波次和结算。同种子作对照，再换种子复验 | 记录关键指令、支出、阶段库存、建筑损失、基地耐久和胜负。标明自动模拟或人工操作 |
| 表现与交付 | 临时或正式的视觉状态、键鼠或触屏的操作状态、已授权的设备范围 | 截图、视频、日志和报告按批次保存在 `Backup/Artifacts/`。正式视觉确认和设备验证分别记录 |

测试筛选为空、测试结果缺项或 Play 入口失败时，先定位原因，再以相同边界复跑。缺失通过明细用完整方法名补验，原始结果保留。自动通关能证明一条路径可达终局。操作可读性、策略取舍和重玩意愿通过真实试玩评估。

## 完成、评审与变更

1. 对照开工卡逐项验收。玩法改动说明玩家现在如何操作、局内有什么变化、在哪些条件下验证过。任何尚待验证的体验、设备或正式表现，明确标注状态。
2. 检查改动范围与回归，核对文档、操作说明和实际入口。记录结论、剩余问题、证据路径及后续依赖。涉及方向变化时更新游戏总纲，并把决定记到执行总清单。
3. 按 `AGENTS.md` 使用中文提交，只暂存本批文件，推送独立 OutpostLoop 仓库并确认远端提交。推送失败时记录本地提交及失败原因。Player Build、发布和正式视觉采用各自遵守已授权范围。
4. 玩家反馈指向某段流程时，先复现整条路径，再检查同类入口。比如建造入口不清楚，应同时核对局内 HUD、建造、升级、暂停和返回之间的职责，再用实际交互复验。

## 当前阶段的开工卡

| 项目 | M1 核心策略切片 |
| --- | --- |
| 目标 | 让一局从开局到终局存在至少两条可解释的打法 |
| 玩家路径 | 看首波预告 → 派工入库 → 分别优先采集站或优先防线 → 中盘应对资源和来敌变化 → 守住或失败 → 结算 |
| 规则与异常 | 以当前 12 分钟六波为比较基线。先记录现有规则下的体验，再根据结果选择要调整的经济、敌波或信息反馈 |
| 验收 | 同一种子、同一起始补给比较两种打法。记录首笔支出、首波和第三波后的库存与建筑损失、终局结果。换一种子复验，并在真实编辑器中完成一轮从开局到结算的试玩 |
| 证据 | 本批开始时建立 `Backup/Artifacts/` 批次目录。自动跑局与实际试玩分别记载，附关键画面和未达标原因 |
