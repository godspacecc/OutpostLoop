# OutpostLoop 首版玩法设计

**版本 v0.2 · 待用户确认**

这是首个完整可玩版的整版方案。当前 Unity 原型作为实现起点，方案包含沿用的原型规则和拟新增的玩法。全部内容经用户明确确认后，按同一版本组织开发和验收。

## 玩家体验

一局 12 分钟。玩家经营一座小型前哨，靠采集和扩建获得足够的收入与火力，撑过六波进攻。主要操作是选资源点、选地块下单、把机动守军调到一侧。单位自动采运、训练和开火。

比如西侧资源丰富。可以先建西侧采集站，把机动小队留在基地附近，等看到敌人再调过去。也可以先在火力薄弱的一侧建路障，给小队争取支援时间，再投入经济。到第四波，玩家从地图看到第二路敌人后，再决定用固定火力顶住哪一边、让小队支援哪一边。

## 一局的流程

| 阶段 | 玩家操作与游戏反馈 |
| --- | --- |
| 开局准备 | 显示胜利条件、补给币余额及起始补给选项。确认开局后扣除所选补给币并入库，生成本局地图与波次 |
| 0 至 2 分钟 | 点资源派工。拿到首批库存后，选择先扩大产出或先补薄弱防线。首波敌人出现后，从场景或小地图观察并调防 |
| 2 至 6 分钟 | 开发第二片资源，观察设施产出与耐久。快速敌人考验火力覆盖，攻坚敌人考验外围设施的防守 |
| 6 至 11 分钟 | 第四波首次双向进攻。决定固定设施守哪边、机动小队支援哪边。第五波回到单向重压 |
| 11 至 12 分钟 | 最终波从两侧来。保住基地并清空全部来敌，等待时限结算 |
| 结算 | 显示胜负、存活时间、击退数量和结算原因。胜利发放补给币，选择再来一局时回到准备页并更换种子 |

## 地图、初始状态与资源

- 地面高位斜俯视，镜头默认围绕基地与周边防线，支持缩放到全图。地图有限，移动边界半径 46 米，四向各有一个外围地块和一个独立炮位。初版全图可见，小地图显示资源、友军和敌人。
- 每局 36 个有限资源点，24 个废料堆与 12 个能源点。单点分别含 18 废料和 8 能源。近基地六个点保证两种资源，资源点避让建筑地块。换种子时刷新资源分布与进攻方向。
- 初始基地耐久 100，东、西各一座炮塔，基地有一名自动采运工人与一支机动小队。默认库存为零，开局补给另计。外围地块初始为空。
- 点场景或小地图中的资源点派工。工人初始移速 5 米每秒，每 0.6 秒采 1 单位，单趟容量 12。装满或采尽后自动返程卸货，改派时先卸现有货物。耗尽节点从地图移除，工人交付剩余货物后待命。
- 采集站与工人共享节点余量。两者同时开采时按工人、采集站顺序结算。已耗尽的节点不再给库存记账。基地库存支付升级和建造费用，两种资源一次性校验及扣除。

## 建造、升级与部队

建造由局内独立侧栏发起，分为「外围扩建」和「炮位管理」，下单时局时继续。每个外围地块可有一座设施，每个炮位可有一座炮塔。先选地块再选设施，炮位页直接选择炮位。

| 建造内容 | 废料 / 能源 | 作用与限制 |
| --- | --- | --- |
| 采集站 | 8 / 0 | 42 耐久，建成时绑定同侧最近未耗尽的节点，每 2.5 秒开采 1 单位直接入库。没有可用节点时该侧无法建站。采尽后停产，设施仍占地 |
| 兵营 | 14 / 3 | 72 耐久，建成后训练 12 秒，完成后产生一支固定驻军并自动开火。兵营摧毁时移除驻军和训练进度 |
| 路障 | 10 / 0 | 150 耐久，拦住从同侧接近的敌人，直到被摧毁 |
| 炮塔 | 16 / 3 | 空炮位直接建成。炮塔自动攻击射程内最近敌人。选中已有炮塔再点空位可免费迁移并保留冷却 |

- 成功下单后立即扣费并出现设施，训练及开采随后随局时推进。库存不足、目标失效或地块占用时给出反馈。炮位与外围地块独立占用。外围设施摧毁后地块恢复为空，可重新付费建设。
- 敌人进场后沿所在方位接近基地。仍在外围的敌人优先攻击所在侧的设施，越过设施的敌人继续攻向基地。外围设施和基地是首版的敌方攻击对象。
- 一次调防命令派整支机动小队去西、东、北或南。小队自动行进并攻击射程内最近敌人。开局待命时也能保护基地附近。兵营驻军留在本侧。
- 炮塔初始射程 14 米，每 0.4 秒最多射击一次，每发 3 点伤害。机动小队和驻军采用 10.5 米射程、0.4 秒间隔与 3 点伤害。火力升级作用于炮塔。

基地升级在独立暂停面板进行。每条路线最多三级，各级统一花费 8/0、16/3、24/6 废料/能源。

| 路线 | 每升一级 |
| --- | --- |
| 采集与运输 | 携带上限加 4，移速加 1 米每秒。采集间隔为 0.6 秒除以 (1 + 0.4 × 等级) |
| 炮塔火力 | 炮塔射程加 3 米，每发伤害加 4 |
| 基地耐久 | 耐久上限加 50，修复 75 耐久，修复后最高为新上限 |

## 六波进攻与胜负

以下时间、敌人编成与来向供关卡规则使用。袭击在敌人实际入场后才通过场景和小地图可见。局内取消袭击预告，包括下一波方向、倒计时与次路提示。主要来向由种子生成，连续两波的主要来向不同。双向波的次路来自对侧，晚 5 秒抵达地图边缘。

| 波次 | 开始时间 | 普通 / 快速 / 攻坚 | 来向 |
| --- | --- | --- | --- |
| 1 | 2:00 | 10 / 0 / 0 | 单向 |
| 2 | 4:00 | 10 / 4 / 0 | 单向 |
| 3 | 6:00 | 12 / 4 / 2 | 单向 |
| 4 | 8:00 | 14 / 6 / 2 | 主路 9 / 4 / 1，次路 5 / 2 / 1 |
| 5 | 10:00 | 16 / 6 / 4 | 单向 |
| 6 | 11:00 | 18 / 8 / 4 | 主路 11 / 5 / 2，次路 7 / 3 / 2 |

| 敌人 | 耐久（第 n 波） | 移速（米每秒） | 近距离伤害（每秒） | 设计作用 |
| --- | --- | --- | --- | --- |
| 普通 | 16 + 3n | 1.5 + 0.1n | 2 | 形成基础进攻压力 |
| 快速 | 10 + 2n | 2.4 + 0.1n | 1 | 更早接触防线，考验常驻火力和发现敌人后的调防速度 |
| 攻坚 | 36 + 4n | 1.0 + 0.05n | 外围设施 5，基地 3 | 拉长交战并威胁外围经济 |

敌人进入目标 2.5 米范围后开始攻击。同屏最多 48 名存活敌人，超出的本波单位等到有名额再进场。基地耐久归零立即失败。12 分钟到时，基地存活且全部敌人已清空才获胜，存活或等待入场的敌人均视为未清空。终局后停止采运、建设和战斗。

## 操作、信息与异常

| 界面 | 操作与时序 |
| --- | --- |
| 战场 HUD | 显示库存、工人载货、基地耐久、本局剩余时间和已发生的波次。左键派工，滚轮缩放，四向按钮调防 |
| 建造侧栏 | `V` 或右下角按钮打开，首次默认选中西侧，此后记住本局最后选择的地块。显示地块、费用、已建建筑耐久和当前产出或训练状态。操作侧栏不同时派工。建设、采运、训练和战斗保持实时 |
| 基地升级与暂停 | `B` 打开独立升级面板，`Esc` 或暂停按钮暂停。打开暂停或升级时收起建造侧栏。退出后回战场继续，真正暂停时禁止实时建造和调防 |
| 事件反馈 | 首次进入战场提示派工、建造、查看小地图和调防。敌人入场后显示在战场和小地图上。设施被摧毁时提示方位与类型，失败区分基地失守和时间耗尽。提示保留在可读区域 |
| 结算和补给 | 胜利一次发放 10 补给币，失败无奖励。每种补给每局可买一份，5 币换 8 废料或 3 能源。只在开始时扣币。保存失败时可以在结算页重试，避免重复奖励。单局状态随重开重置 |

## 相对现有原型的玩法变化

- 移除袭击预告，建造侧栏也按玩家的选择显示地块。第四、六波从对侧分批进场，玩家根据已经出现的敌人判断要支援的防线。
- 敌群加入快速与攻坚两类，并用清晰的临时外观及攻击反馈区分。
- 机动小队开局待命时可以自动保护基地，接到命令后按原有四向调度执行。
- 增加首局操作引导、敌袭与建筑损失反馈，结算说明具体失败原因。

## 内容范围与验收

首版范围是一种地图规则、一种守城模式、两种资源、三种外围设施、固定炮位、两类友军部署方式、三种敌人和六波。自由建造、兵种生产队列、长期城市存档、联机、更多地图和触屏发行均另立版本方案。此次送审范围为 Unity 编辑器键鼠试玩。正式视觉、设备交付和 Player Build 另按项目授权确认。

| 验收项 | 通过条件 |
| --- | --- |
| 操作完整 | 从 Boot 进入，按真实界面完成派工、建造、升级、调防、暂停、继续、结算和重开。两种资源、库存和建筑状态在关键步骤可核对 |
| 策略成立 | 同一种子及补给下，经济优先和防御优先两条路线均有可重复通关路径。记录首笔支出、首波与第三波后的库存、设施损失、布防和最终结果。换第二种子复验 |
| 敌情可读 | 入场前界面不显示袭击方向、倒计时或次路，打开建造侧栏时按固定初始地块或玩家上次选择显示。敌人进入地图后可被发现，玩家仍有调防机会。第四、六波的两路敌人分别在各自入场后可见。敌人类型的差异影响布防，基地或设施受损后可辨识原因 |
| 状态一致 | 同时采集、资源耗尽、重复下单、库存不足、真正暂停、建造期间被摧毁、超额等待进场及终局都按本文结算。胜利奖励只发放一次 |
| 实际试玩 | 使用 Unity MCP 保留限定规则和真实入口验证，另记录至少一局人工操作从开局到结算。人工试玩需要能读出下一步、说明关键取舍并复述胜负原因 |

**本次确认对象为本文 v0.2 的全部玩法、操作、内容范围与验收。** 对具体规则有调整时，先修订整版方案再确认。确认后的版本与确认范围记入[执行总清单](执行总清单.md)。
