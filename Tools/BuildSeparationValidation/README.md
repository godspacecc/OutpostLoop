# 构建发布拆分与持久基线检查

本仓库禁止无范围运行整套测试。本工具保留参考实现，当前仅用 `dotnet build Tools/BuildSeparationValidation/BuildSeparationValidation.csproj` 做编译检查，未执行下述整套检查；不要直接运行默认入口。实际验证请使用 Unity 中明确的非空测试类与数量上限，完整保留 XML 通过项。

58 项检查直接编译产品中的安装器校验、APK 清单生成和发布、资源发布事务、产物发布入口、基线归档恢复、持久版本预留和 CI 核心逻辑。覆盖异地恢复、归档不覆盖、兼容性拒绝、跨平台版本隔离、失败空号、时钟回退、损坏台账拒绝，以及发布目标与宿主基线绑定。所有文件都位于独立临时夹具中，不执行真实 Unity、安装器编译脚本、游戏或资源服务器，也不写真实发布目录或默认持久目录。

第三阶段新增 27 项检查：四种路由、严格参数校验、环境验证不构建、Commit 不符、部分产物保留、构建和发布失败分别报告、显式工具选择、临时配置恢复、真实文件恢复故障、真实子进程的工作锁冲突，以及报告写入失败阻止发布。Windows 下还用真实 PowerShell 执行复制到临时目录的启动器，以本检查程序复制出的 .NET 辅助程序模拟 Unity（临时文件名 Unity.exe），验证冻结请求不能写入、终态回执和缺报告时阻止重试。辅助程序仅能运行注入的验证分支，不包含真实 Unity 构建入口。非 Windows 环境跳过 5 项启动器检查。

Unity 环境通过 Stubs 替代，其中 JsonUtility 使用 System.Text.Json 的公开字段序列化；CI 请求解析使用与产品相同的 Newtonsoft.Json。YooAsset 校验替换为夹具版本文件和 payload 检查。基线文件复制、哈希、路径检查、持久锁和版本台账均使用产品代码。Windows 身份事务使用临时台账和真实持久预留结果，验证本地回滚不退还正式序号。

这些检查不证明真实 AssetBundle、Unity 依赖收集、HybridCLR 元数据兼容性、Player/APK 构建或安装器可安装；编辑器源码另做编译检查，真实打包验收留待授权后执行。运行时仅临时修改测试进程的环境变量来验证路径限制，结束后恢复，不修改系统环境配置。
